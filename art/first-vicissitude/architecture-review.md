# First Vicissitude 架构建议评估

这些建议的主方向合理：共享 Rig 负责动作和 FK，外部美术工具负责几何与 UV，
实体保留核心物理碰撞盒，翼部使用逻辑分段。无需更换动画库或引入大量 PartEntity。
但建议描述的是较早版本，不能把全部条目当作当前缺陷。

## 已有实现与需要修正的判断

- 正式模型已经是 Blender 网格，经导出器生成 mesh JSON 和 Blockbench free mesh 工程。
  `FirstVicissitudeBossModel` 只创建空 ModelPart 骨架，CubeSpec 留给旧美术工具。
  因而不再做一次“从 CubeSpec 迁移到 Blockbench”的工程。
- Joint 的名称、父子关系、pivot 已共享；翼部碰撞盒来自导出的局部网格范围并随 FK 变换。
  装饰网格可绑定现有 runtime_joint，无需每根羽毛都新增 Java Joint。
- Action、起始时间、sequence 和 releaseTick 已存在，但“相同公式必然完全同步”不成立：
  还取决于输入时钟、姿态读取顺序、帧率、实体插值和网络状态到达时间。
- 近战 inflate 是候选查询，后面已有扇形或前向/横向筛选，并非整个 AABB 都受到伤害。
  现有判定仍是近似攻击区域，不是武器网格精确扫掠。

## 此次落地

- 模型和客户端特效共同使用实体的 `poseForRender(partialTick)`，待机时钟统一为世界时间。
  移除按渲染帧累积的姿态平滑，攻击时间使用 partial tick，避免不同帧率造成不同出刀姿态。
- 客户端锚点使用插值位置和 body yaw；待机头部转向同时作用于服务端和客户端 Rig。
- 服务端读取手部、翼部和其他攻击/特效锚点前刷新姿态，避免攻击释放读到上一 tick。
- 横斩、重击和纵斩增加视线检查，保留原有范围与倍率。这是基本遮挡过滤，
  不是刀刃到目标的精确扫掠遮挡检测。
- 动作曲线统一为 `sampleAction(action, ticks, delay)`；保留原先四 tick 跟随及动作数值。
  今后可以在实际动画调校时为不同部位选择延迟，不直接套用建议中未经验证的数值。
- 增加纯 Rig 测试：释放时刻、延迟采样、不同采样频率及动作历史、复制后的 FK 锚点。

## 暂缓的内容

Weapon Rig 与 swept capsule 值得后续做，但需要先校准各难度实际持有的三类武器、
第三人称 item display transform、缩放和刀刃端点，再调整攻击曲线与有效时间窗口。
只按通用镰刀添加几个猜测的锚点，会使视觉与判定更加不一致。
当前保留手部投掷/返回锚点和原有近战区域，不声称已实现精确刀刃碰撞。

取消帧累积平滑后，动作切换可能更明显；如需衔接，应在共享动作曲线中制作收招，
而不是重新加入客户端独有的滞后。游戏内仍需检查低/高帧率出刀、转身移动时的粒子、
投掷接回、墙体遮挡以及动作切换。单元测试不替代客户端实机验收。
