# 无常两阶段血条

本轮重新制作图稿，以 Boss 的晶体头、头后断环、叠层肩甲为中央缩略图标；
一阶段覆羽覆盖血槽，二阶段脱羽后保留骨翼与外露血槽。

- `phase-one-master.png`、`phase-two-master.png`：内置 `image_gen.imagegen` 生成的透明图稿原件。
- `prompts.txt`：完整提示词；一阶段在本轮新制作的二阶段图稿上添加覆羽。
- 原有项目血条没有作为图稿参考或输入。参考资源只用于确定像素 HUD 的布局和表现方式。

运行 `python art/first-vicissitude/tools/make_boss_bar.py`，将图稿裁到可见轮廓，
以最近邻采样适配游戏尺寸，并统一成 24 色及二值透明像素。
脚本重新生成四张游戏 PNG，图稿原件不变。

| 项目 | 规格 |
| --- | --- |
| 底条贴图 | 256×16；空槽与填充各 182×5 |
| 装饰贴图 | 256×32；实际图案 192×30，位于 (32,1) |
| 血槽在装饰层内的位置 | (37,19)；底边描线被下轨遮住，实际可见 4 行 |
| 底条相对事件坐标 | (0,19) |
| 装饰层相对事件坐标 | (-37,0)；和屏幕中央及原版 182px 血条居中对齐 |
| 名称 | 原版位置 y-9，位于图稿上方 |
| 多条血条间距 | 43px；含名称高度与 2px 间隙 |

一阶段客户端只绘制名称与覆羽图稿，不绘制底条/填充，羽片间的负空间不会透出血量。
二阶段使用现有 `LerpingBossEvent` 进度绘制填充；服务端血量、阶段同步和切换时机不变。

检查图在仓库根目录 `build/first-vicissitude-review/boss-bar/`：
`overview.png` 为两阶段四倍像素预览；`stacked-layout.png` 检查名称及叠放位置；
`layout.json` 记录实际透明血槽及尺寸。六档预览为上级目录 `boss_bar_preview.png`。
这些是离线 UI 合成图；实机显示尚未验证。
