# 扬弃逐光（Aufheben Lightward）六件套

## 组成与计数

| 套件位 | 物品 |
| --- | --- |
| 护甲 ×4 | 扬弃逐光头盔 / 胸甲 / 护腿 / 靴子 |
| 剑位 | 神侵恶刃 |
| 斧位 | 熔坠之斧、恋人之斧（同属一个斧位，两只手各拿一把斧仍只算一件） |

- 只有真正穿在四个护甲栏、或拿在主手 / 副手的套件才计数；背包、箱子、地上不算。
- 4 护甲 + 剑 + 斧 = **6/6**。
- 等级就是当前计数的件数；6 级的效果尚未设计，**不写效果、不显示效果行**。

## 各等级效果

| 等级 | 效果 |
| --- | --- |
| 4 | 所有已穿戴 / 手持的套装装备上**已有**的附魔按真实等级 **+3** 参与计算 |
| 5 | 主手上的套装武器解锁「武器攻击更加真实」：轻档探针从 `mediumDamageMethod(..., false)` 改为 `(..., true)`；同时恶刃挥砍打中**认主**的生物时，主人也吃下**等额**的一刀 |
| 6 | 未定，不显示 |

「已有」是硬条件：真实等级为 0 的附魔不会被 +3 凭空生成；真实 NBT 等级也从不改写。
有效等级允许超过附魔自身的 `getMaxLevel()`。

## 实现口径

### 有效等级

`LightwardArmorItem`、`IncursusBladeItem`、`LoverAxeItem` 覆写 Forge 的两个入口：

- `getEnchantmentLevel(ItemStack, Enchantment)`
- `getAllEnchantments(ItemStack)`

两者都读 `EnchantmentHelper.getTagEnchantmentLevel` / `deserializeEnchantments` 的真实 NBT，
再在套装条件成立时统一 +3，保证口径一致、不会重复累加。读取路径之外的附魔逻辑
（直接读 NBT、自己缓存等级等）不在增强范围内。

这两个入口没有持有者参数，因此由 `LightwardSet` 在查询时按 `ItemStack` 实例反查主人：
服务端扫描在线玩家，客户端扫描 `LocalPlayer`。不写 NBT、不维护会过期的运行时标记，
物品离开槽位的同一刻自然失效。

### 提示文字

提示文字全部写在物品自己的 `appendHoverText` 里，不使用 tooltip 事件：

- 四件护甲默认只在名字下面挂一行 `套装效果（x/6）`。
- 按住 Shift 才展开：扬弃逐光套装组成（护甲四件 + 两把武器）、2 / 3 / 4 / 5 级效果。
- 效果只用颜色区分：亮蓝紫 `#9B7BFF` 表示已激活，暗灰表示未激活；不写“已激活 / 未激活”文字。
- 不额外加“按 Shift 查看”的提示行。
- 武器不显示套装文字。
- 套装物品用 `getDefaultTooltipHideFlags` 藏掉原版附魔行，再由 `appendHoverText` 按 NBT 顺序补回；
  生效时显示 `锋利 IV（I+III）`（英文 `Sharpness IV (I+III)`），未生效时保持原版行。
- 原版 `enchantment.level.N` 只翻到 10，有效等级更高时由本模组自己拼罗马数字。

### 5 级「武器攻击更加真实」

同一个门禁（`LightwardSet#unlocksWeaponTopUp`：主手是套装武器且件数 ≥5）管两个读数，整次挥砍只算一次：

- **补满**：`IncursusBladeAttack` 把 `compensateDamage` 传给主伤害、魔法补打和细雪通道。只有主手近战挥砍走这条；
  投掷、飞升等固定档位的技能伤害不因此改变。恋人斧的 `LoverAxeItem.attack` 也用同一个开关：
  主手且件数 ≥5 时补满，否则退回 `mediumDamageMethod(..., false)`（不补满）。
- **连带**：每一记主伤害之后，若被打者认主，就对主人再调用一次**同一个** `applyScytheMeleeDamage`
  —— 同一个 `SCYTHE_MELEE`、同一个攻击者、同一个伤害值、同一个补满开关，不给主人另起伤害类型，
  也不另开派发路径。认主只按 `getOwnerUUID()` 在同一维度解析。细节见
  [docs/mechanics/lightward-transfer.md](../mechanics/lightward-transfer.md)。

护甲提示里仍然只有一行 `5：武器攻击更加真实`，不额外加行。

## 穿戴模型

- 头盔采用「未戴冠者」的独立模型。银灰额带承托三道向后、向内收止的冠脊。冠脊与低矮的后托之间是下沉的铅灰顶面，两侧银白折边勾出受冠的空位。
- 面甲沿中轴隆起，窄眼槽下方由护颊向内收束。额带、护颊与外壳以冷银白为底，暗铅色压在冠位、眼槽和甲片接缝里。额带和太阳穴折边带有折辉铅铋共晶的青金折光，深紫只绘在凹入的眼下泪槽正面。各片随头部转动。
- 胸甲保留背部折翼和冷银近黑配色。原实心躯干与横向胸板由开口胸甲替代，银白侧板向中央聚拢，龛口上方留空。黑色龛室宽 5、高 4.5、深 2 个模型单位，星片悬在后壁前，正面菱形轮廓宽约 2.16。下方连续黑色腹部与腋下黑色衬托分开银甲各层，暗金仅用于铆接点。
- 双臂采用「束光之臂」几何。银白肩盖向后承接翼根，前缘叠片从 4 单位收至 3、2 单位，以短折边搭接侧面护片。上臂与肘部露出连续黑色，侧面护片沿纵向对齐。前臂银白主板从 3 单位收至 2 单位，两侧薄折片贴近主板搭接，后侧保留黑色衬底。银白折面保留少量铋的青色与淡金虹彩。上臂与腕部的细暗金箍线均闭合一圈，从银白护片外侧绕过，转角重叠衔接；前臂的纵向封缄线接到腕箍。
- 折翼从背部上缘的托件起，覆羽压住羽根，长短交错的飞羽沿背侧向后下方收至腰线。羽翼内侧保留阴影，以沿羽片延伸的暗银折面承接侧边与窄羽尖，底面不再整片平涂深色。折翼跟随躯干姿态。物品栏使用「未竟的圣龛」版 16×16 图标。
- 头盔、护腿和靴子的穿戴贴图与 16×16 图标采用胸甲的冷白银与深黑配色。头盔两侧和大腿甲以成对黑色嵌片分区。
- 护腿沿用魂染钢的腰片和倾斜大腿甲。腰片中央为紫青折辉，两侧和大腿甲上角点缀渐变鎏金，银灰折边向下转为深铅灰。穿戴图集保留原 UV 与透明度，甲片跟随腿部姿态。
- 靴子采用「攀附晶根」：保留原有两层方柱靴身，去掉斜置 `boot_wing`。原贴图的银白甲带、黑色间隔、金边与虹彩按最近邻搬入同一张 128×128 图集，靴身 UV 密度为原来的四倍，原图的纹样比例与透明度不变。76 条不等距根路在前、外、后、内四面形成更密的根网，直接绘入靴身材质；主根纹宽约 0.26、支根约 0.16、细根约 0.11 单位，根脉只改变窄线范围内的颜色。仅主根保留 47 小段近乎齐平的晶面，宽约 0.17，前表面高出所在甲层约 0.006 单位；遇到原甲片的透明间隔便下沉到可见的内层，均与本体挂在同级。细网随原甲片起伏，不再组成独立外罩。
- 头盔、胸甲、双臂与靴子几何在 `assets/maledict/models/armor/` 下，供游戏烘焙和离线导出共用。胸甲基础层的 Malum `torso`、`left_arm/left_shoulder`、`right_arm/right_shoulder` 子树分别隐藏。新胸甲与双臂在同一附加图层下，分别绑定 `body`、`left_arm`、`right_arm`，渲染时同步对应姿态。护腿继续使用 Malum 的 `createBodyLayer`；靴子使用独立 `BOOTS_LAYER`，根系与本体分别挂在 `left_foot`、`right_foot`，随对应腿部同步。
- 模型由 `client/item/equipment/lightward/LightwardArmorModel.java` 烘焙，图层由 `MaledictClientSetup` 注册。物品通过 Forge `IClientItemExtensions` 接入，姿态跟随原版护甲渲染器。
- `art/aufheben-lightward/model/` 包含组合工程与四件护甲各自的 `.bbmodel`，均内嵌贴图，另有 `.blend`、三视角预览及原版同机位对照。纹样修改应同步到像素处理源，重建时会更新这些导出文件。
- 重建：`& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --python tools/lightward-model/build_reference_models.py`。
- 晶根路由源为 `tools/lightward-model/build_crystal_root_boots.py`，几何与材质共用根路；修改后先用 Blender 的 `--python` 执行该脚本，再执行上述贴图／工程导出。模型部件允许三轴 `inflate` 数组和 `uv_scale`，控制根宽、端点长度、贴面厚度与 UV 密度；既有标量 `inflate` 和默认 UV 密度保持原行为。`preview-boots-gray-four-views.png` 检查靴身与齐平主根几何，`preview-boots-color-four-views.png` 展示材质内的完整细网。
- 双臂 UV 占用图为 `preview-arm-uv-occupancy.png`，左图显示原臂甲灰色区域，右图显示新臂甲金色区域，两图绿色均为现有胸甲与折翼。新臂甲复用 128×128 图集的下部空余区域。
- 离线验证覆盖九组手臂与躯干姿态的烘焙、姿态同步和顶点绘制，另有摆臂预览。游戏内持武器、举盾和极端姿态的碰撞观感仍需试穿确认。
- 原版第一人称通过 `PlayerRenderer#renderHand` 绘制皮肤手臂与袖层，此路径不绘制当前装备的胸甲模型。当前臂甲无需单独添加第一人称遮挡处理。
