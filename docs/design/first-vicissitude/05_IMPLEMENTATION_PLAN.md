## 验证矩阵

特效按 [10 的技能接入表](10_VFX_INTEGRATION.md)分配到 M3–M6：M4 每个技能先交付最低可读预兆，M5 接飞镰拖尾/牵引，M6 完成柔光、斩弧、转场/死亡与震动润色。不能把所有特效留到末尾才发现范围提示与伤害不一致。

- 保留机制：首击触发及免伤（时长改为 180/140/100/75 秒）、光球压血、四难度配装/伤害上限、Curios 没收与返还、免没收标签、满背包保管和重试、原有生命账本、不同 tick 三次 kill。以最终批准差异为准。
- 状态：出生未参战、首击、转场中受击、二阶段、死亡；第二客户端中途加入、走出/走入跟踪范围。
- 攻击：翼尖四方向释放、近战前摇期间离开范围、目标死亡/下线、投掷撞墙、返回超时、Boss 被移除、飞行期间换难度。
- 存档：一阶段、转场、二阶段空手、弹体飞行、死亡过程保存重载；不重复装备/没收/命中/掉落。
- 外观：正侧背、无粒子灰模、日夜、三武器、两 Boss 同屏姿态互不污染；大翼在画面边缘不会提早消失。
- 场景：大小空间、双翼分段受击倍率与实体/地形碰撞；mobGriefing 与销毁事件允许/拒绝；受困瞬移/无可用落点/邻区未加载/飞镰期间脱困；专服启动及双人同步。破坏策略以澄清后的 D8 为准，不新增 FTB 适配；拒绝破坏不影响脱困。

实施时先 `compileJava`，有生命/状态改动显式执行 `test`；生成资源改动才运行 `runData`。`build` 不能替代 `test`。已有单元测试不覆盖完整 Minecraft 集成，游戏场景必须单独记录。

## 完成记录格式

每个 M 项记录：实际改动文件、所满足的规格条目、命令和结果、游戏场景/截图、未通过项。无环境运行时记“未验证”，不得写已通过。纯文档修改本身不需要启动游戏或构建。

冻结后日常实现不需重复询问类名、helper、UV 或具体角度微调。只有新发现会改变已批准游戏行为、用户预览关卡、必须由用户提供的资源，才产生新问题；在提问前记录具体阻碍和可选解决方案。
