# 女祭司之灵相

能力逐阶段累计：0 阶段提供 0.5 超越预兆；1 阶段生命显影；2 阶段未至之伤；3 阶段灵魂离位。

## 生命显影与性能

16 格内的存活生物显示原版发光轮廓，包括隔墙和隐身目标，仅佩戴者可见。残影实体不参与。
客户端每 tick 查询一次自身视界槽，缓存是否启用；原版渲染已经访问到候选实体时，再做存活、同世界与平方距离判断。
不查询附近实体、不排序或维护目标列表、不做视线射线检测、不逐帧读取 Curios、不发网络包，也不添加发光药效或修改实体标志。
成本为每 tick 一次槽位查询，以及原版已访问实体的 O(1) 判定；复用原版轮廓缓冲与后处理。

### 客户端 mixin 所需的具体能力

`LevelRenderer` 在调用实体渲染器及 `RenderLivingEvent.Pre` 之前，已经通过
`Minecraft#shouldEntityAppearGlowing` 决定是否传入 `OutlineBufferSource` 和运行轮廓后处理。
`RenderLivingEvent` 没有替换该缓冲或开启外层轮廓处理的接口。
Forge 的 `Entity#hasCustomOutlineRendering` 是实体类型自己的覆盖点，不能为其他模组生物和玩家添加当前观察者的规则。
因此客户端只在 `Minecraft#shouldEntityAppearGlowing` 查询实体发光状态的调用点补充生命显影判定，保留原版已为 true 的结果。
使用布尔值重定向，不在每次判定时构造 cancellable 回调对象。
这是为了复用原版路径，避免再绘制附近所有实体模型及额外全屏后处理。

## 灵魂离位

法术直接命中本体后，在其当前位置留下 60 tick 残影。每个目标只有一个；再次直接命中刷新原位与期限。
生成或刷新时，本体仍占据锚点，因此沿随机水平方向偏移 0.5～0.8 格，高度不变；之后保持固定，不逐 tick 避让本体。
客户端通过同步的本体实体 ID 复用本体渲染器，保留模型、贴图、大小与装备图层，绘制青色半透明全亮残影，最后 10 tick 淡出；不再使用灵火粒子代替生物外形。
残影无物理碰撞、不会推挤或被推动；生命值、吸收生命、属性实例、装备、状态效果、Forge capability 与持久模组数据直接读写本体，不维护周期同步的副本。
例如 Malum 的灵魂暴露保存在 `MalumLivingEntityDataCapability.soulData`，残影与本体取得同一份 capability，向任一方暴露灵魂都立即对另一方可见。
经残影施加、升级、强制替换、移除或治愈状态，直接调用本体对应方法，保留本体的免疫规则、效果事件和属性修饰符结算。
残影不运行 `LivingEntity.tick`：状态持续时间、capability 计时与装备属性只由本体推进，避免每个 tick 重复扣时或重复生效。
属性通过实时视图访问本体，但残影的实体追踪器不领取属性同步队列，否则它会提前清空本体待发往客户端的变化。客户端也通过已同步的本体 ID 读取本体状态。
保留 `LivingEntity` 外壳，是因为法术常按 `LivingEntity` 查询目标，`PartEntity` 不会进入这类查询；不需要改造其他模组实体的 multipart 注册。
残影停在原位，法术命中它时将原伤害来源与原始伤害量交给本体的普通 hurt 流程，防御、无敌帧与伤害归属照常计算。
伤害探针可能绕过 `hurt`，经共享的 `setHealth` 扣除本体生命后再对残影调用 `die`。此时残影将死亡流程与原伤害来源交还本体，并恢复来源中的生物／玩家击杀归属；不执行残影自己的死亡和掉落流程。
例如腐枯凋灵由本体处理重塑与最终死亡，最终掉落只在本体位置产生一颗腐枯之星。正常 `hurt` 已处理死亡并移除残影后，不再重复转交死亡调用。
转交期间不创建或刷新残影；实体在本体死亡、离开所在世界或期限到达时清除。残影不保存到存档。

确认序列：t=0 法术击中 A 并留下残影 P；A 移动至 Q；t=20 命中 P 只伤及 A，P 的期限仍为 t=60；
t=40 直接击中 A，唯一残影移动至 Q 附近的随机偏移处，期限刷新至 t=100；t=100 清除。P 同样是初次命中位置的偏移锚点。

状态共享确认序列：A 已有状态 S → P 立即读取同一个 S；向 P 叠加 S → A 的 S 升级一次；
P tick 不推进 S 或灵魂暴露计时，A tick 才扣除一 tick；从 P 移除 S → A 的 S 与其属性修饰符一起移除。
这不改变创造条件：只有法术直接命中本体才创造或刷新残影，施加状态不创造残影，命中残影不刷新期限。
