# 稀有生物召唤印记与图腾仪式

设计与实施说明 v0.4，2026-10-23。来源：下载目录中的 `Maledict_Invocation_Sigil_Design.md`。
本文区分已确认玩法、设计建议与当前实现；首版实际行为以第 1 节和第 12 节为准。

## 1. 已确认的流程

**精魂灌注制作印记 → 主手持印记右键图腾基座 → 当场检查并消耗一枚印记 → 图腾组装与召唤表现 → 生成生物。**

用户确认：

- 条件确认与印记消耗发生在玩家右键时，不延迟到实体生成时。
- 中立、友善生物使用符文木图腾；怪物使用灵魂木图腾。基座和柱子的木材必须一致。
- 启动并消耗印记后，若召唤失败，将已消耗的印记作为掉落物返还。
- 蓝色美西螈印记消耗一桶普通美西螈，不返还空桶；蓝色个体不能作为原料。

原稿中「仅在召唤确实成功后消耗」由上述规则替代。
「确认」指右键时完成条件校验；普通召唤无需额外弹窗或第二次点击。

沿用原稿方向：

- 灌注决定召唤对象与制造成本，图腾负责施行仪式；图腾没有祭品输入槽。
- 多种生物共用少量精魂排列，不为每个生物单独设计一座图腾。
- 这是稀有生物的替代获取途径，避免强制使用目标生物的独有掉落物。
- 印记共用一个物品，以数据区分对象；服务端根据允许定义解释数据。

## 2. 当前版本的实现依据

本地核对环境：Minecraft 1.20.1、Forge 47.4.23、Malum `1.20.1-1.6.7`。
Malum 依赖为 `curse.maven:malum-484064:6646111`；版本来自该 jar 的 `META-INF/mods.toml`。
以下 API 已对照本地映射 jar，而非套用其他 Minecraft 版本的资料。

| 已核对的行为 | 对设计的影响 |
|---|---|
| `SpiritRiteRegistry.getRite(List)` 对精魂列表执行完整、按序匹配，并返回首个匹配项 | 排列自下而上记录；数量、顺序均须一致；注册前检查与现有仪式冲突 |
| 图腾查表只看精魂列表，`getRiteEffect(isSoulwood)` 再选择天然或腐化效果 | 可以用同一排列的符文木/灵魂木分支分别召唤两类生物 |
| 基座 `onUse` 在空闲时开始 `ASSEMBLING`，不是立即生成实体 | 右键消耗与最终生成是两个时间点，必须保存本次召唤目标 |
| `TotemicRiteEffect#doRiteEffect(totem, level)` 没有玩家参数 | 不得在完成时随意找附近持有印记的玩家作为付款人 |
| `ONE_TIME_EFFECT` 完成后基座回到 `IDLE` | 单次效果不等于摧毁图腾；消耗基座和柱子必须另行设计 |
| `TotemicRiteType` 的构造器会调用两个效果工厂方法 | 效果对象不能在构造期间读取尚未赋值的子类字段，可参考现有 `VicissitudeRiteType` |
| 默认仪式图标路径使用 Malum 命名空间 | 自定义仪式要覆写图标路径或明确复用已有图标 |
| 灌注输出可读 NBT，但默认会采用中心输入的 NBT | 输出印记要写入 NBT，并设置 `useNbtFromInput: false` |

本项目已有对应入口：

- `MaledictRecipes.NbtSpiritInfusionRecipeBuilder`：输出 NBT 和关闭输入 NBT 继承的现成范例；当前为私有内部类，实施时按需复用。
- `SummoningRite.install`、`SacrificeRite.install`：在 common setup 中注册 Malum 图腾仪式的范例。
- `VicissitudeRiteConfirmationEvents.findRite`：预读柱子材质、朝向和精魂顺序的范例。
- `SacrificeRiteType`：同一排列具有不同木材分支的范例。

现有 Boss 召唤中有专用的图腾消耗和大范围排他规则，不能直接作为普通生物召唤的默认成本。

## 3. 图腾规则

### 3.1 材质决定允许类别

| 对象 | 固定类别 | 所需图腾 | 补充 |
|---|---|---|---|
| 嗅探兽 | 友善 | 符文木 | 不要求嗅探兽蛋或火把花种子 |
| 悦灵 | 友善 | 符文木 | 不要求先捕获悦灵 |
| 骷髅马 | 非敌对 | 符文木 | 按行为类别归属，不因亡灵主题改用灵魂木 |
| 蓝色美西螈 | 非敌对 | 符文木 | 变种由印记指定 |
| 棕色哞菇 | 友善 | 符文木 | 变种由印记指定 |
| 潜影贝 | 怪物 | 灵魂木 | 保留敌对 AI，需要合法附着面 |
| 唤魔者、远古守卫者 | 怪物 | 灵魂木 | 后续候选，首批不启用 |

类别写在召唤定义中，不根据当前仇恨、是否暂时攻击玩家或 `MobCategory` 名字临时推断。
其他模组生物接入时显式声明类别，并提供所需生成适配。

### 3.2 精魂排列建议

建议先注册**一条仪式、两个木材效果分支**，在符文木上显示「生命召回」，灵魂木上显示「禁忌召唤」。
两类对象共用如下四柱排列，自下而上：

1. 奥术精魂 `ARCANE_SPIRIT`
2. 大地精魂 `EARTHEN_SPIRIT`
3. 神圣精魂 `SACRED_SPIRIT`
4. 澄空精魂 `AERIAL_SPIRIT`

寓意为确定形态、凝聚躯体、赋予生命、唤醒行动；木材决定其自然或腐化途径。
这是候选方案；如果以后需要两套不同排列，可以再拆成两条仪式。
实施时检查完整 `SpiritRiteRegistry.RITES`，发现相同序列即停止注册并报告冲突，不能靠调整注册顺序覆盖其他仪式。

真实精魂还包括邪恶 `WICKED_SPIRIT`、邪术 `ELDRITCH_SPIRIT`、碧水 `AQUEOUS_SPIRIT`、狱火 `INFERNAL_SPIRIT`。
幽影 `UMBRAL_SPIRIT` 不能用于当前版本的图腾雕刻，不纳入排列。
Java 常量对应的精魂类型与 `malum:xxx_spirit` 物品 ID 不应混作同一个序列化字段。

建议普通召唤仅消耗印记，图腾保留、可重复使用；灵魂木召唤也不自动照搬 Boss 的毁塔效果。
若希望怪物召唤另有图腾消耗，需单独确认。

## 4. 召唤印记与数据

物品暂定：`maledict:invocation_sigil`，中文「召唤印记」，英文 Invocation Sigil。
建议同目标同数据可堆叠，每枚对应一个生物；不同定义不能合并堆叠。

建议将原稿直接存实体/变种的示意收敛为**引用召唤定义 ID**：

```snbt
{
  Invocation: {
    Id: "maledict:invocation/sniffer"
  }
}
```

实体、变种、类别、生成策略由定义统一提供，避免物品标签和定义各写一套后互相矛盾。
这个协议是本稿建议，不表示现有存档已有此字段，也不需要为尚未发行的原稿示意添加迁移逻辑。

### 4.1 定义的建议形式

建议以一个专用配方类型承载召唤定义，复用 `RecipeManager` 的数据包重载与配方同步。
这类定义不参与普通工作台合成，也不作为第二份精魂灌注配方展示。

路径示例：`data/maledict/recipes/invocation/sniffer.json`，其定义 ID 为 `maledict:invocation/sniffer`，
与印记中的 `Id` 一致。灌注配方另用 `maledict:spirit_infusion/invocation_sniffer` 等独立 ID。

```json
{
  "type": "maledict:invocation",
  "entity": "minecraft:sniffer",
  "variant": "default",
  "medium": "runewood",
  "spawn_profile": "ground"
}
```

- `medium` 只允许 `runewood` / `soulwood`，对应上文确定的类别规则。
- `variant` 只接受该实体适配器明确支持的值，例如美西螈 `blue`、哞菇 `brown`。
- `spawn_profile` 初期仅实现实际需要的陆地、水域、飞行和附着策略，不能接收任意实体 NBT。
- 数据包可为已支持实体配置定义与成本；新的特殊实体仍可能需要 Java 适配，不能承诺任意模组生物零代码支持。
- 定义丢失、实体未注册、变种或策略不受支持时，印记提示无效，右键不消耗。
- 重载时中止仍在进行的召唤，避免旧定义付款、新定义生成；已消耗的印记按第 7 节掉落返还。

显示名称建议为「召唤印记：嗅探兽」。提示至少显示目标及变种、所需木材、右键启动时消耗。
客户端从同步的定义获得显示信息，最终是否合法仍以服务端为准。
首版一张印记底图配两类色调即可，不要求每种生物独立模型。

## 5. 精魂灌注

每个目标有独立灌注配方，产出一枚带定义 ID 的印记。
产物必须显式关闭输入 NBT 继承，避免中心材料的自定义名称或桶内数据覆盖召唤定义。

输出片段示意，非完整配方：

```json
{
  "type": "malum:spirit_infusion",
  "useNbtFromInput": false,
  "output": {
    "item": "maledict:invocation_sigil",
    "count": 1,
    "nbt": "{Invocation:{Id:\"maledict:invocation/sniffer\"}}"
  }
}
```

中心输入、周边材料与精魂仍按 Malum 真实配方结构由 generator 输出。
以下成本为可讨论的初始数值，不表示已经完成平衡测试；表中中心物品均为 1 件。

| 对象 | 中心物品 | 周边材料建议 | 精魂建议 |
|---|---|---|---|
| 嗅探兽 | 苔藓块 | 泥巴 ×4、骨粉 ×8、小麦种子 ×8、紫水晶碎片 ×4 | 神圣 ×8、大地 ×8、碧水 ×4、奥术 ×4 |
| 悦灵 | 音符盒 | 紫水晶碎片 ×8、羽毛 ×4、金锭 ×4 | 神圣 ×8、澄空 ×8、奥术 ×8 |
| 骷髅马 | 骨块 | 鞍 ×1、铁锭 ×8、紫水晶碎片 ×4 | 邪恶 ×8、神圣 ×4、奥术 ×8 |
| 棕色哞菇 | 红色蘑菇方块 | 棕色蘑菇 ×8、避雷针 ×1、铜锭 ×8 | 大地 ×8、碧水 ×4、狱火 ×4、奥术 ×8 |
| 蓝色美西螈 | 普通美西螈桶 | 热带鱼 ×4、海带 ×8、海晶砂粒 ×4、紫水晶碎片 ×8 | 碧水 ×16、神圣 ×8、邪术 ×8、奥术 ×8 |
| 潜影贝 | 紫颂花 | 紫珀块 ×8、末影珍珠 ×4、末地石 ×8、钻石 ×2 | 邪术 ×16、奥术 ×16、大地 ×8 |

潜影贝配方保留末地探索门槛，且不以潜影壳为必需原料。
骷髅马的亡灵主题可以体现在灌注材料中，图腾材质仍为符文木。

### 5.1 已确认的美西螈桶消耗

用户已选择一对一转化：桶中普通个体和桶一起消耗，不返还空桶。
实现使用普通美西螈桶 ingredient 减去蓝色变种的 partial-NBT ingredient，接受原版四种普通变种，拒绝蓝色变种。
沿用祭坛中心材料直接 `shrink` 的完成路径，不新增祭坛返还物机制；同时关闭输入 NBT 继承，避免桶内变种覆盖印记数据。

## 6. 右键确认、消耗与后续召唤

### 6.1 服务端右键入口

建议在 `PlayerInteractEvent.RightClickBlock` 中处理，因为图腾方块可能先于物品 `useOn` 响应。
沿用项目的 Forge 事件入口和 Malum 公开 API，不需要 mixin。

处理顺序：

1. 尊重已取消的事件、领地或其他监听器的 `DENY`；旁观者不能启动。
2. 只允许主手印记启动；副手不另建一次召唤。
3. 读取有效召唤定义，预读完整图腾，检查木材、柱子朝向、精魂顺序。
4. 检查该基座空闲且没有待执行召唤，检查世界边界、已加载空间、必要生成条件。
5. 任一检查失败：提示具体原因，印记数量不变，不启动该召唤。
6. 建立本次待执行记录，并且只调用一次 Malum 的 `onUse(player, MAIN_HAND)` 启动组装。
7. 确认基座已进入组装状态；若未成功进入则撤销记录，不消耗。
8. 在这次右键处理返回前消耗一枚印记，并同步背包；客户端不重复扣除。

由事件入口接管的交互应取消后续默认方块/物品调用，避免手动调用一次、原流程再调用一次。
正确印记配到错误材质或错误排列时，也要截住这次印记交互，避免误启其他图腾仪式。
其他物品操作已有仪式的行为沿用原流程。

### 6.2 待执行记录

记录至少包含：维度、基座位置、原基座实例、召唤定义快照、实际图腾排列及材质、启动 tick，
以及本次实际消耗的一枚印记的 `ItemStack` 副本，供失败时原样掉落。
一座基座只允许一个记录；启动后的重复点击不再付款、不另行生成。

印记在启动时已经付款，因此后续效果从记录读取对象：

- 不要求玩家继续手持印记，不在结束时再次检查背包或扣除印记。
- 不从附近玩家中重新挑选目标，也不因为旁人靠近而更改召唤内容。
- 建议玩家切换物品、离开或离线均不影响已付款的召唤；图腾和场地仍需有效。
- 同一玩家可以支付不同基座的召唤，不需要额外的全局玩家锁。
- 空手或其他途径触发同一精魂排列时，没有有效付款记录就不能生成实体。

不要把每次召唤的记录存进 `TotemicRiteType` / `TotemicRiteEffect` 实例字段：仪式对象是所有图腾共享的。
记录按第 7 节处理卸载和重启，不能静默遗留可重新兑现的旧记录。

### 6.3 完成阶段

Malum 组装完成后执行单次效果：

1. 领取并标记本次记录为结算中，阻止重复回调再次使用它。
2. 重新检查原基座仍存在，完整柱子、材质、朝向与记录一致；不得使用其他仪式完成旧记录。
3. 重新检查生成位置，创建并通过适配器初始化实体，最后设置指定变种。
4. 使用正常服务端实体加入路径，保留 Forge 初始化和实体加入事件；检查加入结果。
5. 加入成功才播放生物显现的完成效果，并清除记录。此处不再扣印记。
6. 中断或生成失败进入第 7 节的失败处理，不留下能再次生成的记录。

实体默认按自身机制活动，不自动驯服、不自动给鞍或装备；骷髅马建议为普通个体，不启动骷髅陷阱。
建议友善/中立对象生成成年个体，避免随机初始化覆盖蓝色、棕色等指定变种。

## 7. 失败时掉落返还

**已确认：启动前检查失败不消耗；启动并消耗后若失败，将已消耗的一枚印记作为掉落物返还。**
成功生成生物与返还印记是同一次召唤的两种互斥结算结果。

| 情况 | 行为 |
|---|---|
| 定义错误、木材错误、排列错误、启动前无空间、被保护事件拒绝 | 不启动、不消耗 |
| 组装中再次右键，或副手重复触发 | 不追加消耗，不新增召唤 |
| 玩家切换物品、离开、离线 | 建议继续已付款召唤，不作为失败原因 |
| 组装中破坏、替换基座或改变柱子 | 中止本次召唤，掉落返还一枚原印记 |
| 完成时生成位置被堵住、实体创建失败、加入事件被取消 | 不生成生物，掉落返还一枚原印记 |
| 区块卸载、服务器正常重启、数据重载 | 建议中止并转为待掉落返还；生成掉落物所需区块加载后完成返还 |

### 7.1 掉落内容与位置

- 掉落本次实际消耗的一枚印记，保留完整 NBT、自定义名称与目标定义，不根据新配方重新制作返还物。
- 掉落位置建议为原基座上方的空位；位置被占用时，在基座附近已加载空间内寻找可放置物品的位置。
- 基座已被破坏仍按记录中的原位置返还，不依赖方块实体继续存在。
- 不直接放回背包，不需要玩家在线，也不因背包已满而改变处理方式。
- 掉落后的拾取、消失和环境伤害沿用普通物品实体规则。

### 7.2 一次结算与卸载处理

建议为每次已付款召唤保存待执行/待返还状态及原印记副本，按正常世界保存流程持久化。
失败时只允许从待执行转入待返还；进入待返还后不能再生成生物。
掉落物成功加入世界后结束该记录，重复中断通知或效果回调不得再次返还。

若目标区块未加载、附近暂时没有合适掉落位置，或物品实体加入被取消，保留待返还记录，待条件允许后再掉落。
不为返还强制加载区块，也不在掉落物尚未成功加入时清除返还记录。
正常重启后继续处理尚未完成的返还；不需要另建离线邮箱或背包退款通道。

## 8. 生成位置与生物初始化

建议以基座前方约 3 格为表现中心，在水平 2 格、上下 1 格内按固定顺序尝试候选位置。
只搜索已加载区块，不加载远处地形，不移除或穿透图腾方块，不自动造水或搭建容器。
起始检查与完成检查使用相同策略，完成时再次检查用于覆盖玩家在动画期间改变场地的情况。

| 策略 | 初期对象 | 必需条件 |
|---|---|---|
| 陆地 | 嗅探兽、骷髅马、哞菇 | 实体实际碰撞箱无方块/实体占用，脚下有足够支撑，排除危险流体与明显伤害方块 |
| 飞行 | 悦灵 | 碰撞箱净空，避免直接生成在流体或伤害方块中 |
| 水域 | 美西螈 | 足够容纳个体的水域和净空 |
| 附着 | 潜影贝 | 有合法附着面及闭合体积，预留开壳空间，避免刚生成就被迫传送 |

这些是玩家主动召唤的生存和空间条件，不要求自然生成的随机稀有概率、特定结构或雷暴再次出现。
否则仪式无法提供原稿要求的替代获取途径。
必要的维度限制按对象明确列出；不笼统要求所有对象回到原生维度。
怪物在和平难度下应在付款前拒绝；建议完成时再检查，避免生成后立即消失。
不擅自把 `doMobSpawning` 解释为禁用所有玩家主动召唤，需与实际生成路径及服务器约定区分。

普通 `EntityType#create` 不等于完整的生物初始化。
实施时选用 Forge 1.20.1 的初始化入口及合适生成原因，保留相关事件，随后应用允许的变种和年龄。
不得直接反序列化玩家提供的任意 `EntityTag`，也不得在被取消后使用其他路径强行加入实体。

## 9. 视觉、提示与图鉴

建议先复用图腾原有逐柱点亮表现，将精魂流导向前方场地，最后以短暂地面阵纹和粒子聚合显现生物。
符文木表现偏自然明亮，灵魂木沿用腐化精魂的色彩；首版无需为每个目标制作独立召唤动画。

反馈至少区分：无效印记、需要符文木、需要灵魂木、排列不匹配、仪式进行中、场地不足、召唤中断。
灵魂木印记显示「将召唤敌对生物」，不因「禁忌」名称自动增加伤害、地形破坏或 Boss 二次确认。

图鉴应展示：印记制作、同一排列的两种木材分支、右键即消耗、生成场地和失败规则。
先写中文正文，再根据其含义写英文；中文每 13 个可见字符插入字面空格，标点计数。

英文装不下则增加续页，并把中文原文按相同页数重分。使用 `node tools/lang-layout/check-lang-layout.mjs` 检查。
本设计稿不是图鉴正文，不在整份 Markdown 中插入该排版空格。

## 10. 实施顺序与验收

1. 确认候选排列与首批配方数值；失败时掉落返还按第 7 节执行。
2. 实现通用印记、定义加载/同步及提示；以嗅探兽贯通灌注和符文木召唤。
3. 完成右键付款、待执行记录、单次效果、失败清理，验证多人操作。

5. 扩展悦灵、骷髅马、棕色哞菇和已确认原料规则的蓝色美西螈。
6. 增加图鉴、配方展示和最终美术；唤魔者、远古守卫者留待后续设计。

以下具体序列应在实施时固定为测试场景：

| 场景 | 预期 |
|---|---|
| 甲主手两枚嗅探兽印记 → 右键正确符文木图腾 → 组装完成 | 右键返回时剩一枚，完成时生成一只，数量不再改变 |
| 嗅探兽印记 → 正确排列的灵魂木图腾 | 提示需要符文木，不消耗、不开始本次召唤 |
| 潜影贝印记 → 符文木图腾 | 提示需要灵魂木，不消耗、不生成 |
| 甲启动 → 同 tick 副手事件、连续右键、乙点击同一基座 | 合计只付一次、只保留一个召唤记录 |
| 甲启动后切换物品，乙靠近并持另一种印记 | 按甲已付款定义生成，不扣乙物品，也不再扣甲物品 |
| 同一玩家先后启动两个基座 | 每个成功启动各付一枚，各自最多生成一个 |
| 空手触发对应排列 → 单次效果回调 | 缺少有效付款记录，零生成 |
| 启动前生成场地堵塞或交互已被取消 | 印记不变、零生成 |
| 启动后拆柱、替换基座或完成时堵塞场地 | 零生成生物，在原基座附近掉落一枚原印记 |
| 实体加入事件取消或创建失败 → 回调重入 | 零生成生物，只掉落返还一次，不重复付款 |
| 带自定义名称/NBT 的印记付款后失败 | 返还掉落物与实际消耗的一枚印记数据一致 |
| 失败时玩家离线或背包已满 | 仍在图腾处掉落返还，不依赖背包或在线状态 |
| 物品掉落加入被取消或返还区块未加载 | 保留待返还记录，不生成生物，之后只完成一次掉落 |
| 自定义名称/NBT 的材料完成灌注 | 输出仍指向正确召唤定义，不继承无关材料 NBT |
| 蓝色美西螈/棕色哞菇完成初始化 | 指定变种没有被随机初始化覆盖 |
| 区块卸载、重载数据、正常重启后再次交互 | 旧召唤按建议中止并掉落返还，不重复生成生物或印记 |

代码阶段使用必要的编译、纯逻辑测试及针对世界交互的 GameTest/联机验证。
修改资源生成器后运行 `runData`，不直接编辑 `src/generated`；不运行打包任务。

## 12. 当前实现

- 已接入上述六种目标、六条精魂灌注配方、同步的数据包召唤定义和对应创造栏印记。
- 使用第 3.2 节的四柱排列，仪式内部标识为 `maledict_invocation_rite`；同一排列按木材分流。
- 印记最大堆叠 16。右键启动统一消耗一枚，创造模式也遵循同一规则；图腾保留。
- 玩家启动后无需持续手持印记或留在附近。图腾被破坏、场地失效和实体加入被阻止时，原印记在图腾附近掉落返还。
- 待执行与待返还记录按维度保存在 `maledict_invocations` SavedData。卸载中止，正常重启后原待执行记录转为返还，不恢复半途召唤。
- 物品实体加入被取消时保留返还记录并等待重试；掉落成功才清除，不强制加载区块。
- 潜影贝首版使用下方支撑面，检查向上开壳空间；不通过私有方法或 mixin 设置墙面附着。
- 图鉴入口位于奥术全典 `(0, 18)`，在仪式魔法节点上方，包含通用说明及两种木材的图腾排列，不展示具体生物的灌注配方。
- 游戏文案使用「主手手持印记并进行对应的图腾仪式」描述操作。
- 物品模型使用提供的 16×16 透明灰度印记贴图，由客户端 `ItemColor` 按召唤定义的 `tint` 字段着色。
- 颜色不写入物品 NBT；修改定义后，已有印记也会采用新配色。自定义定义省略 `tint` 时保持原灰度。
