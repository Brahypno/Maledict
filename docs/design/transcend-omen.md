# 超越预兆 — Transcend Omen

玩家可见的数值与模型见 [超越预兆机制](../mechanics/transcend-omen.md)。

属性 ID：`maledict:transcend_omen`，默认 0，范围 0–1，服务端计算、属性同步到客户端。
女祭司之灵相在视界槽提供 0.5 超越预兆，后续阶段保留基础加成。
可用 `/attribute @s maledict:transcend_omen base set 0.5` 调试；与饰品加成叠加，属性总值上限为 1。

## 与 Malum 原公式的关系

这是复用 Malum 配方倍率的反向换算，并非整个正向过程的数学逆运算。
对一条来源为 X、各防御目标倍率为 k 的路线，Malum 原处理器实际执行：

- 目标防御增量为 `有效 X × 恶念转化 × k`。
- 配方启用 `ignore_base_value` 时，有效 X 为当前值减去该实体属性实例的底值；否则取完整当前值。
- 来源扣除使用 `MULTIPLY_TOTAL`，修饰数额为 `−恶念转化 × consumptionRatio`。

超越预兆读取防御的完整当前值，以 `min(各防御 / 对应 k)` 得到路线系数，再通过饱和曲线换算增幅。
计算结果 `g` 用作独立 `ADD_MULTIPLIED_TOTAL` 修饰，属性系统先乘以 `1+g`，再裁剪到其范围。
取最小值、路线分流、完整比例扣防御，以及法术属性不得等于注册默认值的前提，均属于本项目确定的反向规则。
单独装备下界合金甲不会改变法术属性，因此不激活路线。

## 已确认的模型

令 M 为减少前的 Malum 恶念转化，R 为超越预兆。正向强度为 `max(M−R, 0)`，反向强度为 `max(R−M, 0)`。
`TranscendOmenUtil.setAmount(entity, sourceId, amount)` 设置一个来源的超越预兆临时加成，
同时减少实体实际的恶念转化属性，并返回未被抵消的反向余量。同一来源复用 ResourceLocation；传入 0 移除该来源。
超越预兆属性本身保留完整加成，不额外减少。移除时撤掉对应修饰，恢复原来的恶念转化；不修改属性底值。

handler 先检查实际恶念转化：不为零则清除、跳过反向；归零后也**只使用余量**，而非全部超越预兆。
例如 M=0.5、R=0.5 时，实际恶念虽已归零，反向余量仍为 0；R=0.75 时只有 0.25 用于反向。
正向由 Malum 原处理器按已经减少的恶念属性执行，未使用 `MalignantConversionHandlerMixin`，
也不在 Malum 的防御增益或来源惩罚之后添加相反修饰来补偿。

反向读取 Malum 已加载的 `malignant_conversion_data`，不维护第二份配方。
每条路线使用完整目标属性值，忽略正向的 `ignore_base_value` 和 `consumptionRatio`：

```text
base = min(各有效目标当前值 / 对应目标倍率)
f(base) = 4 × base / (5 + base)
g = f(base) × 反向余量 S / max(4, 有效来源数 N)
```

来源属性必须存在，且清除预兆旧增益、旧扣除及已失效的正向修饰后，当前值必须不同于属性的注册默认值。
只有默认值的来源整条路线不参与分流，也不触发目标扣除；装备撤下、属性回到默认值后同样退出。
判断比较 `Attribute#getDefaultValue()`，不是实体当前底值；命令或成长机制改变底值也可以激活路线。
倍率非正数或非有限值的目标被跳过。
1.21.1 已确认例外：Malignant Aegis Capacity、Malignant Aegis Recovery Rate、Malignant Aegis Recovery Gain
当前值为 0（或实体没有该属性）时，跳过该目标；既不限制底数，也不参与消耗。
这三项有正值时仍按原判据参与限制与消耗。
Capacity 的默认值是 0（正向转化产生的量，反向阶段已随正向一起被抵消），另两项默认值为 1，正常参与。
其余目标必须存在，属性值有限且为正；有限正输入的除法若溢出到正无穷，该候选按 `Double.MAX_VALUE`
参与取最小值，有限短板仍然生效。没有有效目标或最小候选非正的路线不参与；
不能通过仅有零值 Aegis 目标的路线凭空获得收益。
先采集所有路线，再应用任何修饰，保证来源同时也是另一条路线的目标时也只读取一次干净基线。

饱和曲线对有限的正 base 始终小于 `4`，因此单个来源的增幅上界是 `4 × S / max(4,N)`：
`R=1、N≤4` 时最多 +100%，`R=0.5、N≤4` 时最多 +50%。极小的正数系数会让增幅趋近于 0，而不是线性放大。
`Java double` 在极大 base 下可能把 `5+b` 舍入成 `b`，此时结果允许等于 `4`。

Malum 的加载表以来源属性为键。若扩展代码直接向表中加入同源的多个键，反向结算取系数最高的有效路线，
系数并列时取完整表键 `namespace:path` 字典序最小者。每个来源只计一次份额，也只生成一个增益修饰，
并且只有最终选中路线的目标参与防御扣除。
饱和系数乘以反向余量后，按 `max(4, 有效来源数)` 平分：一条路线占 25%，两条共 50%，
四条及以上用满预算，`N>4` 时每条 `1/N`。总份额始终不超过 100%。
原 `transcendOmen.minimumShare` 配置已移除，旧配置文件里的值不再影响份额。

以下合成例子的两条路线系数均为 1，护甲为 20，反向强度为 50%。
两来源均默认时无路线，护甲为 20。熟练度装备 +1 后，熟练度从 2 乘至 `13/6`，护甲降为 10。
再装备第二条来源 +1，该来源从 1 乘至 `13/12`，熟练度仍为 `13/6`，护甲仍为 10。
撤下熟练度装备后，熟练度恢复默认值 1，第二条仍为 `13/12`。再撤下第二条后，其恢复默认值，护甲恢复为 20。
预兆自身旧加成不能让已回到默认值的来源继续参与。

采用已确认的完整反向比例扣除方案：

- 增幅 `g` 以来源专属稳定 ResourceLocation 的临时 `ADD_MULTIPLIED_TOTAL` 修饰实现，与已有装备乘区相乘。
- 法术属性最终值为原值乘以 `1 + g`，不改写底值，也不按属性点数相加。
- 每个参与有效路线的目标属性统一扣除完整反向比例，以临时 `ADD_MULTIPLIED_TOTAL` 修饰实现。
- 同一目标即使参与多条路线也只扣一次；扣除不随短板或分流份额减小。
- 同时是来源与目标的属性先施加增益，再以 `reductionModifier` 计算扣除。收益系数采集仍使用干净基线。
- 不参与任何有效路线的属性不扣除。

当前 Lodestone 的 `magic_resistance` 默认值为 1，原下载规格的总魔抗 0.25 不可取到。
上述数值测试用允许该数值的击退抗性作为第二目标；用户已确认保留依赖属性的上下限。
目标超过上限时，收益和扣除都按封顶后的当前值计算，例如原始击退抗性 4、当前值 1，扣除 50% 后为 0.5。

固定 M=0.5，依次设置 R=0、0.25、0.5、0.75，结果应为正向 50%、正向 25%、无转化、反向 25%。
跨越零点时清除旧方向的全部修饰；撤掉超越预兆时恢复原有属性。
反向 25% 的实际增幅按上面的公式计算，是饱和后的数值，不再等于余量本身。

## 重算与验证

只在服务端修改属性。使用原生 `EntityTickEvent.Pre`：HIGHEST 优先级在 Malum 的 NORMAL 处理器之前
移除自身旧增益和扣除、调用 util 更新恶念减少量与反向余量，LOWEST 在 Malum 结算后计算反向。
后续装备或药效改变恶念转化时也会重算，不需要改写 Malum 的方法。
缓存检查来源、目标及两种转化属性的底值与每个修饰的 ResourceLocation、数额、操作类型，
因此即使 100% 扣除让目标当前值一直为零，装备变化仍能触发重算。
缓存命中保留原修饰；数据重载会清除已删除路线的增益和惩罚，包括 Malum 的旧正向修饰。
若装备等处理器在 HIGHEST 与 LOWEST 之间修改两种转化属性的底值或修饰，本 tick 不应用旧强度的反向结果，
并使缓存失效，下一 tick 重新抵消与结算。检查原始底值和修饰，因此恶念被完全抵消为零时也能发现变化。

`TranscendOmenTest` 在真实 NeoForge 服务端通过 `EntityTickEvent.Pre` 验证正反向抵消序列、
100% 正向抑制与恢复、默认来源退出、共享目标扣除、满额扣除下的装备变化、事件中途属性变化、
交叉与自目标路线、属性封顶、数据表替换、重复来源键与极端倍率。
四条原生路线使用真实加载的规则，第五条用 Malum 的铁魔法兼容倍率测试分流。
这些场景替换已加载规则表以固定计算输入，不模拟资源包解析或客户端连接。

## Malum 1.8.2 原生路线

继续读取加载后的数据，不覆盖 Malum 的正向规则。新版以护甲与恶念庇护代替旧版部分魔抗/韧性路线。
只有默认值的来源将被排除；表中的收益是乘区增幅，不是属性点数。

| 反向收益来源 | 从防御属性计算的路线系数 |
| --- | --- |
| Magic Proficiency | Armor / 10，Malignant Aegis Capacity / 5 |
| Soul Ward Capacity | Armor / .5，Malignant Aegis Capacity / .25 |
| Soul Ward Integrity | Armor / 10，Malignant Aegis Capacity / 5 |
| Soul Ward Recovery Rate | Armor / 5，Malignant Aegis Capacity / 2.5，Malignant Aegis Recovery Rate / 1 |
| Soul Ward Recovery Gain | Armor / 5，Malignant Aegis Capacity / 2.5，Malignant Aegis Recovery Gain / 1 |

每条有效路线的乘区增幅 `g = f(路线系数) × 反向余量 / max(4, 有效来源数)`。

按零值例外过滤后取最小值。正向转化本身会产生 Aegis，而超越预兆先抵消正向；
零值 Aegis 不作为硬要求，有正值时仍按原判据限制与消耗。
来源仍需有外部提升，且不同于注册默认值；默认来源不参与分配。

以下公式示例选取前四条路线，Recovery Gain 留在默认值。起始护甲 20，反向余量 1，各路线份额 1/4，
Aegis Recovery Rate 为默认值 1（它不像 Aegis Capacity 那样为 0，因此照常限制并扣除）：

| 原 Aegis Capacity | Proficiency 增幅 | Ward Capacity 增幅 | Recovery Rate 增幅 | Integrity 增幅 |
| --- | --- | --- | --- | --- |
| 0 | +28.5714% | +88.8889% | +16.6667% | +28.5714% |
| 2 | +7.4074% | +61.5385% | +13.7931% | +7.4074% |

两种情况护甲均按完整反向比例扣到 0，Aegis Recovery Rate 也从 1 扣到 0；第二行 Aegis Capacity 同样扣到 0。
不在新版路线中的护甲韧性与 Magic Resistance 保持原值。
例如第二行，若原熟练度 2、容量 1、恢复速率与稳固度均为 2，则最终分别为
`58/27 ≈ 2.1481`、`21/13 ≈ 1.6154`、`66/29 ≈ 2.2759`、`58/27 ≈ 2.1481`。

1.20.1 分支的 Malum 把容量路线的护甲倍率写作 `1`，20 护甲时系数 `20`，`R=0.5、N=4` 的容量增幅正好是
`+40%`，也就是原下载规格的验收基准。1.8.2 改成 `0.5`，同样的护甲得到 `+44.4444%`；
公式和基准不变，差值来自 Malum 自己的配方倍率，本实现不覆盖它。
