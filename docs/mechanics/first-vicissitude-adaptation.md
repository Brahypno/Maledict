# 第一化身的「适应 N」

- 配置：`firstVicissitude.adaptationLevel`，默认 **2**，`0` 关闭。
- 实现：`DamageAdaptation` + `FirstVicissitudeBossEntity.modifyIncomingDamage`。

## 模型

适应看的不是「谁打的」，而是**最近命中的几条伤害消息**。每条伤害都带一个死亡消息 id
（`DamageSource#getMsgId()`，例如 `player`、`arrow`、`scythe_sweep`、`magic`、`freeze`），窗口只记 id。
所以两个人拿同一把武器打，算同一条消息。

- 窗口大小 = N，按「最近命中」排序，队首最新。
- **先记账，再判定**：这一击先进入窗口（已在窗口里就挪到队首；不在就插入队首，并把**最久没被打到**的
  那条连同它的计数一起淘汰），然后才决定倍率。
- 同一批伤害按**调用顺序逐次处理**，顺序会影响结果；同一个 tick 也算一批。
- 只有**这一击之前就已经在窗口里**的消息才被减免，倍率是 `e^-(它在被记住期间挨过的次数)`。
- 被淘汰的消息**不留任何记忆**：计数丢弃，下次命中重新算第一次。
- 同一 tick 内一条消息**只记一次**。一次挥砍会把同一条消息打中多次（补量探测会再用同一个 source 打一下，
  奥术通道也在同一个 `LivingHurtEvent` 里结算），按「每次调用」计数等于让一次挥砍自己适应自己。同 tick 的
  后续调用复用第一次的倍率，下一 tick 才是新的一批。
- 抑郁符文（`RuneOfMelancholiaItem`）用的是普通 `adapt`，每次调用都算，不走上面的批内去重。

## 实例：默认 2，三条消息轮换

```
A: 记 [A]      判 A 原本不在 → 满伤
B: 记 [B, A]   判 B 原本不在 → 满伤
C: 记 [C, B]   判 C 原本不在 → 满伤   （A 被淘汰，计数丢弃）
A: 记 [A, C]   判 A 原本不在 → 满伤   （B 被淘汰，计数丢弃）
B: 记 [B, A]   判 B 原本不在 → 满伤   （C 被淘汰，计数丢弃）
C: 记 [C, B]   判 C 原本不在 → 满伤   （A 被淘汰，计数丢弃）
```

**永远满伤。** 这就是为什么三连轮换（例如只靠 `player` / `arrow` / `magic` 交替）打第一化身完全不吃适应。

## 不同配置的实际效果

| 配置 | 同一条消息连续命中 | 2 条消息轮换 | 3 条消息轮换 |
| --- | --- | --- | --- |
| `adaptationLevel = 1` | 从第 2 次起减免 | 永不减免（上一条总在判定前被淘汰） | 永不减免 |
| `adaptationLevel = 2`（默认） | 从第 2 次起减免 | **从第 3 次命中起**减免，逐次按 e⁻¹、e⁻²… | 永不减免 |
| `adaptationLevel = 3` | 从第 2 次起减免 | 从第 3 次命中起减免 | **从第 2 轮起**减免 |

`adaptationLevel = 1` 只对「同一条消息连续命中」生效，这是「先记账再判定」的直接结果，不是特例。

## 和武器通道的关系

神侵恶刃一次挥砍在扫击路径上会落下三条消息：`scythe_sweep`、`magic`（奥术通道）、`freeze`（霜冻通道），
所以默认 2 的窗口下它的伤害**永远不会被适应**——三条消息轮换，谁也不够久地留在窗口里。

奥术与霜冻这两跳的来源与顺序见 [incursus-blade-channels.md](incursus-blade-channels.md)。
